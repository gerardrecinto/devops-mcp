Ask Claude why production is down. Get answers from your live systems.

devops-mcp is an MCP server that gives Claude read access to Kubernetes, Jenkins, GitHub Actions, AWS, Azure, GCP, ServiceNow, Slack and Microsoft Teams, so one question replaces six dashboards. Every call is audited.

For on-call, SRE and platform engineers who use Claude Code or Claude Desktop.

pipx install "git+https://github.com/gerardrecinto/devops-mcp.git"
claude mcp add devops-mcp -- devops-mcp
devops-mcp --check

Install

Python 3.11 or later with pipx. Docker works too. Install from GitHub: the devops-mcp package on PyPI is a different project and is not this one.

pipx install "git+https://github.com/gerardrecinto/devops-mcp.git"
claude mcp add devops-mcp -- devops-mcp
devops-mcp --check

With no other setup it reads your current kubeconfig, so "which pods are failing?" answers about your real cluster. Any service you have not configured returns a plain "not configured" error. devops-mcp --check shows what is connected and what to do next.

Azure, GCP and Slack need extras:

pipx install "mcp-devops[azure,gcp,slack] @ git+https://github.com/gerardrecinto/devops-mcp.git"
docker pull ghcr.io/gerardrecinto/devops-mcp:latest
claude mcp add devops-mcp -- docker run -i --rm --env-file ~/.devops-mcp/.env \
  -v ~/.kube:/home/devops-mcp/.kube:ro ghcr.io/gerardrecinto/devops-mcp:latest

The image includes every integration.

Want to see the output shape with no credentials? Add the demo flag. Every response is then labelled as sample data and is not real information about your systems. Remove the flag once you connect real ones.

claude mcp add devops-mcp -e DEVOPS_MCP_DEMO=1 -- devops-mcp

Set up your credentials

Pick the systems you use. The page writes the Claude Desktop config and a matching ~/.devops-mcp/.env with placeholders. Each service is independent, and any service without credentials is skipped. Nothing here is sent anywhere.

How it works

  
An MCP server over stdio. Claude decides which tools to call, the server runs them against your systems and returns plain results.

  

    
1
Read-only by default
The infrastructure tools observe: pods, logs, builds, metrics, incidents. They cannot apply, delete, restart or trigger anything.

    
2
Each service stands alone
A module that fails to import or has no credentials is skipped and logged. The rest still register, so a partial install works.

    
3
Every call is logged
Each tool call is appended to ~/.devops-mcp/audit.log with its parameters, secret-like ones redacted. Credentials come only from environment variables.

  






  

    What this does not do
    
    
      
  • It cannot demo live here. The tools need your credentials and your systems, so this page shows the catalog and builds your config instead.
    • 
      
  • The Slack and Teams post tools send messages. They are the only writes and are refused unless the operator sets DEVOPS_MCP_ENABLE_WRITES=1. Give those tokens narrow scopes anyway.
    • 
      
  • It reports what the APIs return. Claude's explanation of a root cause is a hypothesis to check, not a verdict.
