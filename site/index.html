Ask Claude why production is down. Get answers from your live systems.

devops-mcp lets Claude read your Kubernetes, Jenkins, AWS and other DevOps systems, so on-call engineers ask one question instead of checking six dashboards.

pipx install "git+https://github.com/gerardrecinto/devops-mcp.git"
claude mcp add devops-mcp -- devops-mcp
devops-mcp --check
Browse the tools

Needs Python 3.11 or later and pipx. It installs from GitHub: the devops-mcp name on PyPI is a different project.

Put simply: MCP is a standard plug that lets Claude use outside tools, and this one lets it look at your servers and build systems.

Then ask a question

With no setup it uses your current kubeconfig. Ask Claude "Which pods are failing in my cluster?" and it answers about your real cluster. devops-mcp --check shows what is connected.

You: "The API deployment has been stuck for 20 minutes. What's going on?"

Claude:
  [k8s_get_failing_pods("production")]
  api-server-7d9f8b-xk2p9  CrashLoopBackOff  restarts: 14

  [k8s_pod_logs("api-server-7d9f8b-xk2p9", tail_lines=30)]
  [09:10:03] FATAL  postgresql://db-prod:5432: Connection refused

  [k8s_get_events("production", event_type="Warning")]
  OOMKilling  Pod/db-prod-0  "Memory limit exceeded"  count: 3

  db-prod-0 was OOMKilled, so the API pods cannot reach the database.

illustrative Pod names, incident number and times are made up. This is not output from a real system.

Docker, extras, Claude Desktop and sample data
    
Azure, GCP and Slack need extra packages:

    
pipx install --force "mcp-devops[azure,gcp,slack] @ git+https://github.com/gerardrecinto/devops-mcp.git"

    
Docker (the image includes every integration):

    
docker pull ghcr.io/gerardrecinto/devops-mcp:latest
claude mcp add devops-mcp -- docker run -i --rm --env-file ~/.devops-mcp/.env \
  -v ~/.kube:/home/devops-mcp/.kube:ro ghcr.io/gerardrecinto/devops-mcp:latest

    
Claude Desktop: add this to ~/Library/Application Support/Claude/claude_desktop_config.json and restart.

    

    
No credentials yet? The demo flag returns sample data. Every response is labelled as sample data and is not real information about your systems. Remove the flag once you connect real ones.

    
claude mcp add devops-mcp -e DEVOPS_MCP_DEMO=1 -- devops-mcp

  






  
What it does and does not do

  
Put simply: Claude can look at your systems but not change them, apart from chat messages you switch on, and a private log records every look.

  
    
    
  • Read-only by default. It cannot apply, delete, restart or trigger anything. The only writes are Slack and Teams messages, and they stay off unless you set DEVOPS_MCP_ENABLE_WRITES=1.
    • 
    
  • Every call is logged to ~/.devops-mcp/audit.log, with secret-like values hidden.
    • 
    
  • It reports what the APIs return. Claude's guess at a root cause is a hypothesis to check, not a verdict.
    • 
    
  • No live demo here. The tools need your credentials and systems, so this page shows the catalog.
    •
