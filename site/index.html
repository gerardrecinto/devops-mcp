How it works

  
An MCP server over stdio. Claude decides which tools to call, the server runs them against your systems and returns plain results.

  

    
1
Read-only by default
The infrastructure tools observe: pods, logs, builds, metrics, incidents. The README states they cannot modify infrastructure.

    
2
Each service stands alone
A module that fails to import or has no credentials is skipped and logged. The rest still register, so a partial install works.

    
3
Every call is logged
Each tool call is appended to ~/.devops-mcp/audit.log with its parameters. Credentials come only from environment variables.

  






  
Install

  
Python 3.11 or later with pipx. Docker works too. This is not the devops-mcp on PyPI, which is a different project.

  

    


pipx install "git+https://github.com/gerardrecinto/devops-mcp.git"
claude mcp add devops-mcp -e DEVOPS_MCP_DEMO=1 -- devops-mcp

# extras for the services you use
pipx install "mcp-devops[azure,gcp,slack] @ git+https://github.com/gerardrecinto/devops-mcp.git"

    

    


docker pull ghcr.io/gerardrecinto/devops-mcp:latest

claude mcp add devops-mcp -- docker run -i --rm \
  --env-file ~/.devops-mcp/.env \
  ghcr.io/gerardrecinto/devops-mcp:latest

      
Without credentials a tool returns a clear "not configured" error. Set DEVOPS_MCP_DEMO=1 to get sample data labelled as such, which is how you can try it with no cluster.

    

  






  

    What this does not do
    
    
      
  • It cannot demo live here. The tools need your credentials and your systems, so this page shows the catalog and builds your config instead.
    • 
      
  • The Slack and Teams post tools send messages. They are the exception to read-only, so give those tokens narrow scopes.
    • 
      
  • It reports what the APIs return. Claude's explanation of a root cause is a hypothesis to check, not a verdict.
